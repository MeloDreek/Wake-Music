# 音乐库分组与封面背景回归检查

## 自动检查

在项目根目录执行：

```sh
ruby Tests/Collections/run-grouping-regressions.rb
ruby Tests/Collections/run-palette-regressions.rb <已启动的模拟器UDID>
```

分组脚本提取项目实际的 Singer / Album / Genre 实现，配合最小模型替身运行；不读取或修改用户音乐库。当前 24 项断言覆盖空白标签、重复及多艺术家、演示歌曲的显示名、精确成员匹配、Unicode 规范化、文件夹/歌词排除、曲序和连续修改/删除后的刷新。

取色脚本将实际 ArtworkPalette.swift 和本地 DominantColors 源码编译成独立模拟器测试 App（`com.wakemusic.tests.palette`）。默认库路径为 `/Users/kaka/Documents/本地公开库/DominantColors`，可通过第二个参数指定其他路径。当前 80 项断言覆盖黑白灰、浅色、高饱和、多色、边框封面、缓存、一致性、快速切图的过期回调、空封面重置及布局尺寸。只使用合成图片，不访问实际音乐或账号。

取色测试对不透明白字与渐变端点检查至少 4.5:1 对比度；这不等同于完整界面的所有半透明文字都经过无障碍审核。

## 实现约束

### 详情页后续调整验收

- 操作按钮居中排列，播放按钮标准宽度 160pt，随机和导出 44pt，图标分别为 14pt / 17pt；保留至少 44pt 点击区域。
- `LocalMusicAccessory` 同时供 MusicTableViewCell 与 CollectionTrackCell 使用：完整标签显示原本地菜单，缺失标签显示指纹入口。
- 模拟器确认完整菜单包含音频指纹识别、喜欢、添加到歌单、删除；缺失标签的入口可进入现有标签编辑页并返回。未执行识别、修改、移动或删除用户文件。
- 普通版与 Pro 版的 arm64 模拟器构建通过。菜单的破坏性操作仅检查确认流程代码，未对用户文件进行实操。

保留 DominantColors，不增加依赖。背景采用筛选后的封面多色、亮度/饱和度限制、柔和渐变和切换淡入淡出；这是接近参考图的本地实现，不是 Apple Music 私有算法。像素处理在后台串行队列执行，带有界缓存和过期结果校验。保留播放器的高斯模糊、遮罩、自定义背景选项，只更新封面主色调模式。缺失封面使用中性色，不以占位图的荧光色生成背景。

构建验证应指定已启动的 arm64 模拟器并设置 `ONLY_ACTIVE_ARCH=YES ARCHS=arm64`。本机曾出现通用模拟器双架构构建成功，但输出 App 的调试动态库仍旧的情况；安装前应确认产物更新时间或 UUID。
